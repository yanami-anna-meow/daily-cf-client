# 使用指南

[English](../user-guide.md) | 简体中文

Daily CF 用于浏览[小羊肖恩的每日一题](https://github.com/Yawn-Sean/Daily_CF_Problems)，并通过 GitHub 提交解答。提示、题解和参考代码在应用内阅读，原题通过系统浏览器打开。下载与构建方法见 [README](../../README.zh-CN.md)。

## 浏览题库

**最新题目**显示仓库中最新的题单，不限定为电脑日期对应的当天。历史题库读取仓库里的全部有效日期，包括未来日期；每天可以有任意数量的题目。

**历史题库**按月份和日期从新到旧排列。题号、标题、提示、日期搜索，以及难度和题目类型筛选，都作用于完整题库。左侧月份目录用于跳转到该月第一个匹配结果，不会缩小搜索范围。定位日期同样保留完整列表和筛选；从详情返回时会恢复原来的浏览位置。

最低和最高难度都包含边界。只填一边表示单边限制，两边留空表示不限，也会显示未标注难度的题目。设置任意一边后，不包含难度未知的题目。范围错误时会提示，不会自动交换上下界。

难度保留仓库原本的写法：`1700` 仍显示 `1700`，`*1700` 保留星号，颜色采用 Codeforces 的分段配色。Gym 和 CF Round 根据原题链接判断，与难度是否带星号无关。

原题按钮会把仓库提供的链接原样交给系统默认浏览器，包括查询参数和锚点。Codeforces 登录和验证都在浏览器中完成，客户端不抓取或内嵌题面。题名与链接不一致时，界面会显示资料来源警告，便于核对。

## 更新题库与离线阅读

桌面端在本地保留一份公开题库，启动、切换页面和点击**刷新**时都会检查更新。首次下载较慢，后续通过 Git 增量取得新版本所需的数据，不需要安装 Git。

更新期间先显示已有内容。完整的新题库读取成功后，再整体替换旧列表；远端版本没有变化时，核对后可复用本次运行中已有的完整结果。首次加载会显示进度，也可以搜索已经读到的部分。

更新失败时，仍可阅读已有内容，同时显示失败提示。成功更新确认远端文件已删除后，当前视图也会移除它们；这不会删除你的本地解答文件或已加入提交列表的内容。

同步会检查本地 Git 数据是否损坏，能修复时先重新下载并核验，再切换到修复后的版本。修复需要联网和足够的磁盘空间。目录不安全或仓库身份不符时，程序会停止同步，不会接管该目录。详细边界见[安全与隐私](security.md#本地题库与完整性检查)。

设置和加密登录状态与题库分开保存。PR 和账号信息仍通过 GitHub API 读取，受其请求额度限制；题库更新成功不代表 PR 数据也刷新成功。

浏览器开发预览不建立本地 Git 仓库，仍通过 GitHub API 和公开文件接口读取题库，因此浏览题库本身也会消耗 API 请求额度。

## 更新客户端

在**设置 → 软件更新**中检查新版本。程序读取[客户端仓库](https://github.com/yanami-anna-meow/daily-cf-client/releases)的最新正式发布版本，与题库更新相互独立，无需登录 GitHub。检查本身不会下载、安装或重启程序。

发现新版本后，可以查看发布说明，再选择下载。程序会根据当前运行版本的操作系统、架构和安装形式选择文件：

| 当前运行版本 | 下载文件 |
| --- | --- |
| Windows 安装版 | Windows NSIS 安装程序 |
| Windows 免安装版 | Windows 免安装可执行文件 |
| macOS，从 DMG 或 ZIP 安装 | macOS DMG |
| Linux AppImage | Linux AppImage |
| Linux DEB | Linux DEB |

架构以当前运行的程序为准：`x86_64` 仍下载 `x86_64`，`arm64` 仍下载 `arm64`。因此，通过模拟运行的 Intel 版本也会下载 Intel 版本。需要更换架构或安装形式时，请到发布页选择对应文件。开发构建或无法识别的安装形式也会提供发布页入口，不会自行选择安装包。

下载时显示进度，可以取消或重试。提供下载文件前，程序会核对其完整大小，并根据发布页中的 `SHA256SUMS.txt` 检查 SHA-256；打开文件或在文件管理器中显示前还会再检查一次。未下载完整或校验失败的文件不能通过更新功能打开。

Windows 安装版、macOS DMG 和 Linux DEB 下载完成后，点击**打开安装包**并确认，交给系统打开，再按照安装程序或软件包管理器的步骤完成更新。当前客户端仍然保持运行，请在退出前处理好待提交内容并保存设置。有未保存的修改时，确认窗口会提醒。

Windows 免安装版和 Linux AppImage 下载完成后，可以打开文件所在位置，退出旧版本，再自行替换。下载的 AppImage 会设置执行权限。请将新文件放到计划长期使用的位置，再从那里打开。

校验通过的下载文件保留在数据目录的 `updates` 文件夹中，实际数据目录可在**设置 → 本地文件**中查看。安装完成且没有安装程序再使用这些文件后，可以手动删除不再需要的下载文件。客户端会保留它们，避免删除安装程序可能仍在读取的文件。

每一步都由你选择，程序不会静默安装或自行重启。安装包原有的签名限制仍然适用，包括 macOS 的临时签名，详见[安全与隐私](security.md#软件更新)。

0.3.24 及更早版本没有这项功能，需要先手动下载并安装一次 0.3.25，之后便可在客户端内检查和下载后续版本。

## 题解与参考代码

题解支持 Markdown、公式和代码块。参考解答展示所有匹配作者的代码，可以按语言筛选、切换文件和复制原文。代码使用应用内置的 JetBrains Mono 字体。

已识别的格式包括 C、C++、Python、Java、Rust、Go、C#、JavaScript、TypeScript、Kotlin、Ruby、Swift、Scala、PHP、Pascal、D、Haskell、OCaml、F#、Perl 和 R。未知扩展名按纯文本显示。其中 `.c` 是 C，`.C` 是 C++，`.h` 显示为 C / C++。

过大或无法安全高亮的内容会退回纯文本，不改写或截断源码。参考文件读取上限为 1 MiB。语法高亮不代表编译或正确性检查。

## 登录并选择 Fork

点击**登录 GitHub**，在 GitHub 页面输入客户端显示的验证码并授权。也可以使用个人访问令牌。权限、令牌登录和高级 OAuth 设置见 [GitHub 登录配置](github-setup.md)。

创建 PR 前，需要在提交窗口或**设置 → Fork 仓库**中明确选择来源仓库。界面同时显示保存提交分支的来源仓库，以及接收 PR 的上游仓库。

- 从列表选择已有 Fork 并确认；即使只有一个候选，也不会自动选中。
- 输入 `owner/repository`，绑定改名后的 Fork 或候选列表中没有显示的仓库。
- 点击**创建 Fork**，核对完整仓库名后确认创建，再保存设置或确认**使用这个 Fork**。

来源仓库必须属于当前 GitHub 账号，且与配置的上游处于同一 Fork 网络。客户端不会自行选择、创建或更换 Fork。如果当前账号本来就拥有配置的上游，也可以明确选用它作为来源；投稿仍通过独立分支和 PR 完成。

即使列表里已有候选，创建入口仍然可用，但 GitHub 可能返回已有 Fork 或拒绝所填名称。此时客户端会说明实际结果，不会把旧仓库当成新建成功并自动绑定。修改 Fork 不会改变上游，也不会迁移已有 PR。

### 提交前的同步

预览 PR 只读取 Fork 状态。确认提交后，客户端按以下规则处理 Fork 默认分支：

| Fork 状态 | 处理方式 |
| --- | --- |
| 与上游一致 | 不修改 |
| 仅落后上游，没有独有提交 | 非强制快进，并核验结果 |
| 已包含上游，另有自己的提交 | 保留个人提交；从核对过的上游版本创建投稿分支 |
| 与上游分叉 | 停止提交，提示先在 GitHub 处理分叉 |

客户端不会强制重置 Fork 默认分支。同步 Fork 和创建 PR 是不同的 GitHub 操作，可能已经同步成功，但后续上传失败；请按错误提示重新预览后重试。Fork 被删除或改名后，需要重新选择绑定，客户端不会自动替换。

## 提交解答

代码在自己的编辑器里编写和测试，客户端负责导入、预览，并从提交列表生成一个新 PR。

1. 在题卡或详情页点击**加入提交列表**。
2. 选择 UTF-8 源码文件并填写本份文件的署名，核对扩展名、生成的文件名和代码预览。署名初始为空，没有本地默认值。
3. 加入文件后继续浏览其他题目，或从提交列表添加更多文件。未登录时也可以准备列表。
4. 准备好后登录 GitHub，确认 Fork，点击**预览 PR**。核对来源与目标仓库、路径、差异和 PR 内容，并逐项确认需要覆盖的文件。
5. 点击**提交 PR**。所有实际有变化的文件一起生成一个新 PR，成功后清空本次列表。

客户端不修改已有 PR；需要调整已创建的 PR 时，请在 GitHub 操作。

### 文件与扩展名

语言预设用于快速填写扩展名，也可以自行修改或填写其他扩展名。导入时保留文件实际扩展名和大小写，不会把 `.cc` 改成 `.cpp`，也支持 `d.ts` 等复合扩展名。无扩展名的文件需要补填；不合法的文件名字符或路径会在字段旁提示。

一次可提交 1–50 个文件，每个最多 256 KiB，规范化后的 UTF-8 代码合计最多 5 MiB。文件必须是有效 UTF-8，不能含空字节。每份文件的说明和整个 PR 的共享说明分别最多 2,000 个字符。

同一道题可以在一个 PR 中提交多份，只要生成的目标路径不同，例如使用不同署名或扩展名。路径与提交列表中已有项相同时，会展示差异并要求确认替换；这不代表已经授权覆盖上游文件。

文件始终提交到题目原始日期对应的目录，不会改为当天。

### 已有文件与覆盖确认

加入文件时会只读检查上游是否已有相同路径。文件已存在或检查失败时会提示，仍可确认加入；最终预览会重新检查。

若已有文件内容不同，预览会显示完整路径、旧代码和差异，需要逐文件勾选确认。确认绑定到当时查看的文件版本；提交前远端版本发生变化时，会停止并要求重新预览。变更发生在新的投稿分支中，不直接写入上游默认分支。

与上游相同的文件会标记为无变化，不列入最终 PR 的变更明细；所有文件都相同时不会创建空 PR。提交文本会去除 UTF-8 BOM、统一为 LF 换行并补齐末尾换行，本地原文件不受影响。

### 列表会保留多久

提交列表、署名和说明只保存在本次运行的内存中。关闭列表弹窗或切换页面会保留，退出、刷新整个应用或崩溃后无法恢复。正常关闭和刷新会先提醒尚有内容未提交，程序不保存解答草稿。

请求失败后可以重试，客户端会核对本次提交是否已经产生分支或 PR，再继续处理。内容变化后的请求不会被用来修改已有 PR。提交成功表示 PR 已存在，不代表 Codeforces 已通过评测或维护者已经合并。

## PR 状态与提交记录

提交记录来自当前 GitHub 账号向配置上游发起的 PR，包括通过网页或其他工具创建的记录。一个包含多道题的 PR 仍计为一个 PR。

题目关联根据真实变更文件路径识别，不依赖标题、正文或文件名中的署名。同题在所有日期的关联 PR 放在一个列表中，按创建时间从新到旧排列，打开、合并和关闭状态都会显示。

| 题卡背景 | 含义 |
| --- | --- |
| 淡紫色 | 至少有一个关联 PR 已合并 |
| 淡绿色 | 没有已合并 PR，但至少有一个正在等待合并 |
| 中性背景 | 仅有已关闭 PR，或没有可确认的关联 |

具体记录和各状态数量会与颜色一起显示。加载、失败或结果不完整都有单独提示，没查到不能证明从未提交过。已有 PR 只是提醒，不会阻止再次投稿。

GitHub 搜索最多返回 1,000 个 PR，单个 PR 最多读取 3,000 个变更文件。客户端会显示已经取得的记录，并在结果可能不完整时提示。删除文件和其他目录的变更仍列在 PR 详情中，但不计作提交解答。PR 数据不会保存为本地投稿台账。

## PR 模板

**设置 → Pull Request 模板**提供一套标题和 Markdown 正文模板，单题与多题提交共用。把光标放在输入框中后，可以点击变量插入。设置页用示例预览，投稿时使用实际文件。

| 变量 | 内容 |
| --- | --- |
| `{{date}}` | 最早题目日期，例如 `2026-10-07` |
| `{{date_compact}}` | 紧凑日期，例如 `20261007` |
| `{{date_range}}` | 最早至最晚日期；相同时只显示一个日期 |
| `{{problem_id}}` | 仓库题号，例如 `cf1234a` |
| `{{problem_label}}` | 上游题目名称 |
| `{{problem_url}}` | 原题链接 |
| `{{rating}}` | 保留星号的难度，或未评级提示 |
| `{{rating_source}}` | 小羊估算、CF 官方或未知 |
| `{{problem_type}}` | Gym、CF Round 或未知 |
| `{{language}}` | 语言名称 |
| `{{extension}}` | 实际扩展名，不含开头的点，保留大小写 |
| `{{author}}` | 各文件现场填写的署名 |
| `{{filename}}` | 生成的文件名 |
| `{{path}}` | 完整仓库路径 |
| `{{notes}}` | PR 共享说明 |
| `{{login}}` | 当前 GitHub 用户名 |
| `{{problem_count}}` | 按日期和题号去重后的题目数 |
| `{{file_count}}` | 实际变更文件数 |
| `{{problem_list}}` | 题目、文件和各项说明的 Markdown 表格 |
| `{{file_list}}` | 仓库路径的 Markdown 列表 |

多文件提交时，各字段按输入顺序分别去重并连接。需要保留题目、难度和文件之间的对应关系时，用 `{{problem_list}}`。存在实际变更时，最终模板只展开有变化的项目。

展开后的标题必须为单行，以最早题目日期的 `YYYYMMDD` 加一个空格开头，最多 256 个字符；正文最多 60,000 个字符。未知变量、不完整的括号和保留的 `daily-cf-` 标记会被拒绝。变量只做文本替换，不运行代码。

## 设置

修改后需要保存。未保存就离开时，可以选择**保存并离开**、**放弃修改**或**继续编辑**；保存失败会保留表单。保存设置不会把提交列表写入磁盘。

### 语言

可选跟随系统、简体中文或 English。系统首选语言以 `zh` 开头时使用中文，其他语言使用英文。界面、日期、错误提示和原生菜单会切换，仓库资料、代码和自定义模板保留原文。

### 外观

初始有绿色、粉色、蓝色和黑白四个方案，默认选中绿色。每个方案有名称及浅色、深色两组配色。添加方案会复制当前方案供继续编辑；自带与新增方案使用相同操作。

每组可设置按钮底色、强调色、页面背景、卡片背景和正文文字五项，支持选色器或 `#RGB`、`#RRGGBB`。强调色用于链接和操作文字，与按钮底色独立；正文对比度不足时会提示。浅色、深色和跟随系统模式与配色方案分别选择。

**恢复默认方案集**需要确认，会把表单恢复为最初的四个方案并选中绿色，保存后才生效。放弃表单可以保留此前方案；语言、明暗模式和其他设置不会一起重置。

### 本地文件

**设置 → 本地文件**显示实际配置和数据路径。可以定位 `data.json`，或打开包含设置、加密会话和题库的数据目录。尚未生成配置文件时会打开它的上级目录。这些操作不会保存或丢弃当前表单。

手动编辑这些文件前请先退出程序。保存范围和登录保护方式见[安全与隐私](security.md#本地数据)。
