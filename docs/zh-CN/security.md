# 安全与隐私

[English](../security.md) | 简体中文

本文说明 Daily CF 保存哪些数据、向 GitHub 发送什么，以及提交前进行的检查。日常操作见[使用指南](user-guide.md)，源码构建见[贡献指南](../../CONTRIBUTING.zh-CN.md)。

## GitHub 凭据

浏览器登录采用 GitHub Device Flow。主进程请求设备验证码，在你通过 `https://github.com/login/device` 授权时轮询结果。客户端不接收 GitHub 密码，也不需要 OAuth Client Secret；Client ID 是公开标识。

Device Flow 的访问令牌和设备密钥只由主进程处理，界面收到供用户输入的验证码、验证地址、过期时间和账号信息。手动令牌登录时，令牌必然经过输入框和专用 IPC 调用，再由主进程核验和保存。界面没有读回已保存令牌的接口。

Device Flow 请求 `public_repo` 权限。它覆盖当前账号有权操作的公开仓库，不只限于每日一题仓库。客户端自身的检查将投稿流程限制在配置上游和经过核验的来源仓库，但不会缩小 GitHub 签发令牌的权限。详见 [GitHub 权限定义](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps)。

修改 Client ID 需要确认，并会取消尚未完成的设备授权。它改变后续授权使用的应用，不改变已有令牌。错误 ID 可能导致下次登录失败；**恢复默认**将安装包内置 ID 填回表单，仍需保存。详见 [GitHub 登录配置](github-setup.md)。

退出登录会清除当前凭据和本地会话，不会撤销 GitHub 服务器上的授权。可在 [GitHub Applications](https://github.com/settings/applications) 撤销 OAuth 应用，或在[个人访问令牌设置](https://github.com/settings/tokens)中删除手动使用的令牌。

## 本地数据

桌面数据根目录位于 Electron `appData` 下的 `Daily CF`，不同上游仓库使用各自的子目录。**设置 → 本地文件**显示实际路径。启动参数 `--user-data-dir=<绝对路径>` 可为测试选择独立的数据根目录，但不会改变远端上游。

| 文件或目录 | 内容 |
| --- | --- |
| `session.enc` | 已验证的 GitHub 令牌；安全存储可用时用 Electron `safeStorage` 加密 |
| `data.json` | 明文设置、来源仓库绑定和 PR 模板 |
| `library.git/` | 公开上游 Git 对象、仓库身份和当前版本指针 |
| `data-legacy-<摘要>.json` | 迁移时保留的原始设置或数据 |
| `data-corrupt-<时间戳>.json` | 无法读取的设置或数据文件备份 |

提交列表、选中的代码、各份文件的署名和说明只保存在内存中。关闭列表弹窗或切换页面会保留，正常关闭窗口或刷新会先询问是否丢弃；崩溃或强制退出可能直接丢失。客户端不修改或执行本地原始解答文件。PR 记录来自 GitHub，不保存为本地投稿台账。

旧版本可能保存过草稿、历史记录或署名偏好。迁移只恢复仍受支持的设置；覆盖含非空旧草稿或历史记录的文件前，会先按内容摘要创建备份，备份失败则停止保存。旧文件和备份可能仍含这些内容，移除功能不等于安全擦除了旧数据。

设置和会话先写入独占创建的临时文件，再重命名，以减少写到一半中断造成的损坏。存储层会在支持的平台请求私有文件和目录权限，实际效果取决于操作系统及文件系统。

`safeStorage` 依赖操作系统账号及密钥存储。Linux 密钥环不可用或使用 `basic_text` 后端时，客户端只在内存中保存令牌，退出后需重新登录，不会降级为明文保存。已有会话无法解密时也需要重新登录。详见 [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。

公开题库、设置和迁移备份没有加密。同一系统账号下的软件可能有权读取或修改应用数据，安全存储也不能保护已经被入侵的系统账号。卸载应用不代表数据已清除；手动编辑、备份或清理目录前请先退出程序。

## 本地题库与完整性检查

桌面端通过内置的 `isomorphic-git` 读取公开上游，不需要系统 Git。首次浅层下载包含当前版本的完整文件树，后续增量更新。默认分支名和版本从远端取得，不固定为 `main` 或 `master`。

题库是没有工作区的 bare 对象库，不执行上游代码、hooks 或子模块，也不用来推送解答或维护个人 Fork；投稿通过独立的 GitHub API 流程完成。

每个题库都有仓库身份标记。当前版本指针记录受限的 `objects-<UUID>.git` 目录名、版本和分支。同步检查目录边界、文件类型和仓库身份；身份不符、不安全的根路径和无法识别的非空目录会使操作停止。所检查的对象路径拒绝符号链接与硬链接，普通 Windows 短路径别名在目录结构核验后允许使用。客户端不会通过替换身份标记接管用户仓库。

同步核验实际 Git 对象数据、pack/index 关系、对象标识和当前快照可达内容。发现损坏后，可以从公开远端建立并核验新的对象库，再原子替换当前版本指针；每轮同步最多尝试重建一次。网络、磁盘空间和权限问题会直接报告，不会因此反复下载。

旧对象库迁移时保留原件。旧代、修复失败留下的对象库和未知文件不会被递归删除，因此磁盘占用可能增加。目录身份不安全时不自动修复。即使界面内存中仍有旧内容，损坏的磁盘快照也可能无法继续读取。

题库传输只访问 `https://github.com` 上配置仓库的 Git 读取端点，不发送账号令牌或 Cookie，并拒绝 HTTP 重定向。Git 下载协议中的 POST 请求也是读取，不会发布提交或分支。

当前资源边界如下：

| 操作 | 限制 |
| --- | --- |
| 单次 Git 下载 | 传输 256 MiB |
| 一轮同步，含修复重试 | 180 秒，另有 210 秒工作线程保护 |
| 单个展开后的 Git 对象 | 128 MiB |
| 一次核验的展开数据或物理对象文件 | 分别最多 512 MiB |
| 单份题单、题解或参考代码文本 | 1 MiB |

这些限制针对具体操作，不代表整个进程内存或长期磁盘占用的上限。超限会报告失败。检查也不能保证抵御已经取得同一系统账号权限的其他进程对文件的任意改动。

### 更新时保留已有内容

本地读取只使用已发布的快照，不联网、不创建目录、不触发修复，也不把尚未发布的新对象库当成可用版本。启动、切换页面和刷新仍会检查远端。

程序在内存中保留有数量上限的解析结果。同步成功后，版本和目录信息未变时可以复用完整题库；否则先读取新快照，再整体替换旧视图。失败或中止时，继续显示一致的旧视图并提示更新未完成；首次加载可先显示本轮已读到的部分。

确认删除或成功返回空内容时，会清除相应旧内容。网络错误可以保留旧结果，但不会被报告为刷新成功。内存复用不能授予投稿权限，也不能跳过最终 GitHub 校验。

浏览器开发预览通过 GitHub API 和公开文件接口读取，不建立本地 Git 对象库。它可以在本次运行中保留页面结果，但不能恢复桌面端的磁盘题库。

## 窗口、链接和文件

- Electron 启用上下文隔离、沙箱和 Web 安全检查，关闭渲染进程的 Node.js 集成。
- preload 只开放具体业务操作，不提供任意 IPC 或文件系统访问；主进程核对调用来源并校验输入。
- 窗口禁止自行导航、弹出新窗口和请求设备权限。外部链接经主进程校验后交给系统浏览器。
- 允许主机为 `github.com`、`codeforces.com`、`www.codeforces.com`、`espresso.codeforces.com`、`yawn-sean.github.io` 和 `docs.github.com`。Codeforces 原题链接允许 HTTP 或 HTTPS，其他主机要求 HTTPS。带账号密码或未允许端口的地址会被拒绝；有效链接保留原查询参数和锚点。
- 内容安全策略将脚本限定在应用资源并禁用插件对象。Markdown 通过受限的 React 组件渲染，不作为原始 HTML 插入页面。

原题在系统浏览器中打开，客户端不抓取题面 HTML、不读取该浏览器的 Cookie，也不向其传递 GitHub 令牌。

参考代码和导入文件都是只读文本。高亮只生成文字与样式，不生成可执行 HTML；客户端没有编辑、编译或运行代码的功能。文件选择器按大小限制读取 UTF-8 文本，拒绝非法编码和空字节。

剪贴板只在用户主动复制时写入。专用接口校验输入并限制为 1 MiB UTF-8 文本，不提供读取或监视剪贴板的接口，也不会读回验证写入。复制失败后仍可手动选择文本。

## 网络请求

客户端没有自建账号服务器、使用分析或崩溃遥测，使用以下服务：

| 服务 | 用途 |
| --- | --- |
| `github.com` | 公开 Git 下载和设备授权 |
| `api.github.com` | 账号、Fork、PR 查询和投稿 |
| `raw.githubusercontent.com` | 浏览器预览中的公开文件 |
| `avatars.githubusercontent.com` | 用户头像 |
| 系统默认浏览器 | 用户主动打开的链接，包括 Codeforces 原题 |

账号和投稿 API 只向 GitHub 携带访问令牌，公开 Git 下载和原始文件读取不携带。认证和仓库请求拒绝重定向，界面收到整理过的错误，不直接显示认证服务的原始响应。

## Fork 与投稿边界

上游提供题库并接收 PR，来源仓库保存投稿分支。发布构建默认以 `Yawn-Sean/Daily_CF_Problems` 为上游，除非构建时明确配置了其他仓库。修改来源绑定不会修改上游。

绑定需要明确选择并通过 GitHub 核验。来源必须可写、属于当前账号，且 GitHub 返回的 Fork parent 或 source 指向配置上游。如果当前用户就是上游拥有者，也可以明确绑定上游，通过独立分支投稿。只读候选查询不会自动选择或创建 Fork；无效或缺失的绑定会阻止操作，不会回退到其他仓库。

预览只读取状态，不发布代码。确认提交后，客户端再次核对账号、来源、上游、日期、题号和生成路径。Fork 默认分支仅在单纯落后上游时非强制快进；个人提交会保留，历史分叉则停止。新 PR 分支从核对过的上游版本创建，避免带入 Fork 的其他工作。

一次投稿接受 1–50 份文件，每份最多 256 KiB，规范化代码合计最多 5 MiB，所有路径必须唯一。扩展名可自行填写并保留大小写，但不能含路径分隔符、控制字符、文件名禁用字符或结尾的点与空白。生成文件名最多 255 个 UTF-8 字节。导入文本须为有效 UTF-8 且不含空字节；提交会规范化 BOM 和换行，不修改原文件。

覆盖需要明确确认目标路径及旧文件的 Git blob SHA。后端在同步 Fork 或发布前重新读取远端；缺少确认或 SHA 已变时，要求重新预览。替换提交列表中的项目只是本地决定，不代表远端覆盖授权。内容未变化的文件不计入实际 PR 变更，全部未变化时不能创建空 PR。

发布会先准备 Git 对象、文件树和提交，再创建分支引用与 PR。这些 API 调用不是一个事务：Fork 快进或分支创建可能已经成功，后续步骤却失败。客户端不会自动删除这些结果。重试先核对账号、仓库、父提交、文件内容和 PR 文件，再返回或继续同一次操作；只有标题、路径或客户端标记相同不足以确认。重试不会修改已经创建的 PR 的标题、正文、文件或分支。

PR 模板只做一次文本替换，不执行代码、不递归解释变量。未知变量、格式错误和保留的 `daily-cf-` 标记会被拒绝。标题最多 256 个字符，正文最多 60,000 个字符。PR 和提交中的客户端元数据用于核对重试，是公开信息，不是授权凭证。

PR 查询限定为当前作者和配置上游，返回后再次核验，题目关联来自真实变更路径。GitHub 搜索限制为 1,000 个 PR，单个 PR 文件清单最多 3,000 个；程序保留可读结果并标明可能不完整。切换账号会丢弃旧账号的结果。已有 PR 在客户端中保持只读。

## 问题反馈

请提供客户端版本、操作系统、复现步骤和脱敏的错误信息，不要在公开 Issue 中附上访问令牌、设备密钥或会话文件。漏洞问题请通过维护者提供的私密渠道联系。项目的检查范围见[依赖审计](dependency-audit.md)和[发布指南](releasing.md)，通过这些检查不代表不存在漏洞。
